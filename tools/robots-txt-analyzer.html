🔎 How to Analyze Your Robots.txt

This tool parses your robots.txt file and shows you every rule, grouped by User-agent. Use the URL tester to check if any specific URL would be crawled or blocked for a given bot.

Common Robots.txt Mistakes

  1. Accidentally blocking all bots with Disallow: /
  2. Blocking CSS/JS files (prevents Google from rendering pages)
  3. Case-sensitive paths (robots.txt paths are case-sensitive)
  4. Missing trailing slash on directory rules
  5. Sitemap URL pointing to wrong path

How the Rule Engine Works | Rule Engine कैसे काम करता है

Search engines apply robots.txt rules using a "longest match wins" principle — when multiple Allow/Disallow rules could apply to the same URL, the one with the longest matching path takes priority, regardless of the order it appears in the file. This tool's URL tester implements exactly this logic, so the Allowed/Blocked verdict you see here reflects how Googlebot and most modern crawlers actually interpret your rules, not a simplified first-match approximation. | Search engines robots.txt rules को "longest match wins" principle से apply करते हैं — जब कई Allow/Disallow rules एक ही URL पर लागू हो सकते हैं, तो file में उनकी order चाहे जो भी हो, सबसे longest matching path वाला rule priority लेता है। इस टूल का URL tester ठीक इसी logic को implement करता है, इसलिए यहाँ दिखने वाला Allowed/Blocked verdict बताता है कि Googlebot और ज़्यादातर modern crawlers आपके rules को actually कैसे interpret करते हैं, न कि किसी simplified first-match approximation को।

Crawling vs Indexing | Crawling बनाम Indexing

One of the most misunderstood points about robots.txt is that it controls crawling, not indexing. A URL disallowed in robots.txt can still appear in Google's search results (often with no description) if other pages link to it — robots.txt only stops the crawler from fetching that URL's content, it does not guarantee the URL stays out of the index. To reliably keep a page out of search results, a noindex meta tag or header is required on that page itself. | Robots.txt के बारे में सबसे ज़्यादा misunderstood बात यह है कि यह crawling को control करता है, indexing को नहीं। Robots.txt में disallowed कोई URL फिर भी Google के search results में दिख सकता है (अक्सर बिना description के) अगर दूसरे pages उससे link करते हैं — robots.txt केवल crawler को उस URL का content fetch करने से रोकता है, यह guarantee नहीं देता कि URL index से बाहर रहेगा। किसी page को reliably search results से बाहर रखने के लिए उस page पर noindex meta tag या header ज़रूरी है।

Limitations to Keep in Mind | ध्यान रखने योग्य Limitations

This tool analyzes whatever text you paste in — it does not fetch your live site's robots.txt automatically, so you must copy the current content yourself (for example, by visiting yoursite.com/robots.txt). It also cannot simulate every edge case of every search engine's crawler, since some engines interpret wildcards or ambiguous directives slightly differently; always confirm critical changes using Google Search Console's own robots.txt testing tools before relying solely on this analysis. | यह टूल उसी text को analyze करता है जो आप paste करते हैं — यह आपकी live site का robots.txt अपने आप fetch नहीं करता, इसलिए आपको current content खुद copy करना होगा (जैसे yoursite.com/robots.txt पर जाकर)। यह हर search engine के crawler के हर edge case को भी simulate नहीं कर सकता, क्योंकि कुछ engines wildcards या ambiguous directives को थोड़ा अलग तरीके से interpret करते हैं; critical changes के लिए हमेशा Google Search Console के अपने robots.txt testing tools से पुष्टि करें, सिर्फ़ इस analysis पर निर्भर न रहें।

Frequently Asked Questions | अक्सर पूछे जाने वाले प्रश्न

Q. Does this tool fetch my website's robots.txt automatically? | क्या यह टूल मेरी website की robots.txt को अपने आप fetch करता है?

Q. Does robots.txt stop a page from being indexed? | क्या robots.txt किसी page को indexed होने से रोकता है?
Not reliably — it blocks crawling, not indexing; a disallowed URL can still appear in search results if other pages link to it. Use a noindex tag to prevent indexing. | पूरी तरह नहीं — यह crawling को रोकता है, indexing को नहीं; disallowed URL फिर भी search results में दिख सकता है अगर दूसरे pages उससे link करें। Indexing रोकने के लिए noindex tag उपयोग करें।

Q. What does "Disallow: /" mean for my whole site? | मेरी पूरी site के लिए "Disallow: /" का क्या मतलब है?
It blocks every page on the site from that User-agent's crawler — this is almost always accidental and the tool flags it as a critical error. | यह उस User-agent के crawler को site के हर page को block करने के लिए कहता है — यह almost always गलती से होता है और यह टूल इसे critical error के रूप में flag करता है।

Q. Why does blocking CSS and JS files cause problems? | CSS और JS files को block करने से समस्या क्यों होती है?
Google needs to load your CSS and JS to render the page the way a real visitor sees it; blocking them can hurt how your page is understood and ranked. | Google को page को उस तरह render करने के लिए आपकी CSS और JS load करने की ज़रूरत होती है जैसे एक real visitor देखता है; उन्हें block करने से page को समझने और rank करने के तरीके को नुकसान पहुँच सकता है।

Q. How does the "longest match wins" rule work? | "Longest match wins" rule कैसे काम करता है?
When both an Allow and a Disallow rule could match a URL, the rule with the longer, more specific path takes priority, regardless of which line appears first. | जब कोई Allow और Disallow rule दोनों किसी URL पर match हो सकते हैं, तो जो rule का path लंबा और अधिक specific होता है वह priority लेता है, चाहे कौन सी line पहले आती हो।
