💡 Canonical URL Tips

🔒
Always Use HTTPS
Canonical URLs should always use https:// even if your site redirects HTTP to HTTPS.
🔗
Absolute URLs Only
Always use full absolute URLs (https://example.com/page/) — never relative URLs (/page/).
📋
Remove Tracking Params
UTM parameters, session IDs and click tracking create duplicate URLs. Canonical should point to the clean URL.
📄
Self-Referencing
Every page should have a self-referencing canonical, even if there's no duplicate. It's an SEO best practice.
🔄
Consistent Trailing Slash
Choose either /page/ or /page — then stick with it sitewide. Both are fine, but mixing creates duplicate content.
📱
Pagination
For paginated content, the canonical of page 2, 3... should still point to that page — not page 1.

🔗 What is a Canonical URL?

A canonical URL is the "master" version of a page that you want search engines to index when multiple URLs have the same or very similar content. The rel="canonical" HTML tag tells Google: "This is the definitive version of this content — ignore all duplicates and consolidate any ranking signals here."

Common causes of duplicate content that canonical URLs fix include: HTTP vs HTTPS versions, www vs non-www, trailing slash vs no slash, URL parameters (UTM, session IDs, filter parameters), printer-friendly versions, and paginated versions of pages.

How to Add

  1. Generate the canonical tag using this tool.
  2. Paste it inside the <head> of the relevant page.
  3. Every page should have exactly one canonical tag.
  4. Canonical should match the URL shown in address bar (after redirects).

Why duplicate content needs a canonical tag | Duplicate content को canonical tag की ज़रूरत क्यों है

The same piece of content is often reachable at several different URLs — with and without "www", with a tracking parameter like utm_source, or with and without a trailing slash — and search engines treat each variant as a separate page unless told otherwise. | एक ही content अक्सर कई अलग-अलग URLs पर पहुंचा जा सकता है — "www" के साथ और बिना, utm_source जैसे tracking parameter के साथ, या trailing slash के साथ और बिना — और search engines हर variant को अलग page मानते हैं जब तक उन्हें बताया न जाए।

A self-referencing or cross-referencing canonical tag tells Google exactly which URL is the "master" version, consolidating ranking signals onto that one URL instead of splitting them thinly across several near-duplicate addresses. | एक self-referencing या cross-referencing canonical tag Google को exactly बता देता है कि कौन-सा URL "master" version है, ranking signals को कई near-duplicate addresses में बंटने के बजाय उस एक URL पर इकट्ठा कर देता है।

Frequently Asked Questions | अक्सर पूछे जाने वाले प्रश्न

Q. What exactly does a canonical tag do? | Canonical tag असल में क्या करता है?
It tells search engines which URL is the definitive, "master" version of a page's content when the same or similar content is reachable at more than one address. | यह search engines को बताता है कि किसी page के content का definitive, "master" version कौन-सा URL है, जब एक जैसा या similar content एक से ज़्यादा address पर पहुंचा जा सकता हो।

Q. Where do I paste the generated tag? | Generated tag को कहाँ paste करूं?
Inside the <head> section of the HTML page it refers to, anywhere before the closing </head> tag. | उस HTML page के <head> section के भीतर जिसे यह refer करता है, closing </head> tag से पहले कहीं भी।

Q. Should every page have its own canonical tag, even with no duplicates? | क्या हर page का अपना canonical tag होना चाहिए, duplicates न होने पर भी?
Yes — a self-referencing canonical (pointing at the page's own clean URL) is considered an SEO best practice even when no duplicate currently exists. | हाँ — एक self-referencing canonical (page के अपने clean URL की ओर point करता हुआ) बिना किसी duplicate के भी एक SEO best practice माना जाता है।

Q. Why remove UTM and tracking parameters from the canonical URL? | Canonical URL से UTM और tracking parameters क्यों हटाएं?
Tracking parameters create technically different URLs for the same content, so including them in a canonical tag would defeat its purpose of pointing to one clean master version. | Tracking parameters एक ही content के लिए technically अलग URLs बना देते हैं, इसलिए canonical tag में उन्हें शामिल करना एक clean master version की ओर point करने के उद्देश्य को ही खत्म कर देगा।

Q. Should I use a relative or absolute URL in the tag? | Tag में relative या absolute URL इस्तेमाल करूं?
Always absolute — a canonical tag should always use the full URL including https:// and the domain, never a relative path like /page/. | हमेशा absolute — canonical tag में हमेशा https:// और domain सहित पूरा URL इस्तेमाल होना चाहिए, कभी /page/ जैसा relative path नहीं।

Q. Does trailing slash vs. no trailing slash really matter? | क्या trailing slash होने या न होने से असल में फ़र्क़ पड़ता है?
Yes, to a search engine example.com/page/ and example.com/page can be seen as two different URLs, so pick one style and apply it consistently sitewide via your canonical tags. | हाँ, search engine के लिए example.com/page/ और example.com/page दो अलग URLs हो सकते हैं, इसलिए एक style चुनें और canonical tags के ज़रिए पूरी site पर consistently लागू करें।

Q. How should paginated pages (page 2, 3...) use canonical tags? | Paginated pages (page 2, 3...) canonical tags कैसे इस्तेमाल करें?
Each paginated page should canonicalize to itself, not to page 1, since each page shows distinct content that search engines should be able to index separately. | हर paginated page को खुद को canonicalize करना चाहिए, page 1 को नहीं, क्योंकि हर page अलग content दिखाता है जिसे search engines अलग से index कर सकें।

Q. Can a canonical tag point to a completely different domain? | क्या canonical tag पूरी तरह अलग domain की ओर point कर सकता है?
Yes — this is common for syndicated content, where the republishing site canonicalizes to the original source domain to avoid duplicate-content competition. | हाँ — यह syndicated content के लिए common है, जहाँ republish करने वाली site duplicate-content competition से बचने के लिए original source domain को canonicalize करती है।

Q. What's the difference between a canonical tag and a 301 redirect? | Canonical tag और 301 redirect में क्या फ़र्क़ है?
A 301 redirect actually sends visitors and search engines to a new URL and the old one stops loading, while a canonical tag lets the original URL still load normally but tells search engines to credit a different URL for ranking purposes. | 301 redirect असल में visitors और search engines को एक नए URL पर भेज देता है और पुराना URL load होना बंद कर देता है, जबकि canonical tag original URL को सामान्य रूप से load होने देता है पर search engines को ranking के लिए किसी दूसरे URL को credit देने के लिए कहता है।

It guides search engines going forward, but re-crawling and re-consolidation of ranking signals can take days to weeks, so results are not instant. | यह आगे के लिए search engines को guide करता है, पर ranking signals का re-crawling और re-consolidation होने में दिनों से हफ़्तों लग सकते हैं, इसलिए results instant नहीं होते।
