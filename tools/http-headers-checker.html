🌐 What are HTTP Headers?

HTTP headers are metadata sent by a web server with every response. They control how browsers cache the page, who can embed it, how search engines treat it, and whether security features like HTTPS enforcement and XSS protection are active.

Key SEO Headers

  1. X-Robots-Tag — Server-side equivalent of meta robots (works for non-HTML files like PDFs)
  2. Content-Type — Ensures charset=utf-8 for correct rendering
  3. Location — 301/302 redirect destination
  4. Link rel=canonical — Canonical URL via header (alternative to HTML meta tag)

Key Security Headers

  1. Strict-Transport-Security (HSTS) — Forces HTTPS
  2. Content-Security-Policy (CSP) — Prevents XSS attacks
  3. X-Frame-Options — Prevents clickjacking
  4. X-Content-Type-Options — Prevents MIME sniffing

About This Tool | इस टूल के बारे में

Every time a browser requests a web page, the server replies with a status code and a set of HTTP headers before any HTML is even sent — these headers quietly control caching behaviour, security protections, redirect destinations, and hints that search engines use when deciding how to index a page. | जब भी कोई browser कोई web page request करता है, server कोई भी HTML भेजने से पहले एक status code और HTTP headers का एक सेट भेजता है — ये headers caching behaviour, security protections, redirect destinations, और search engines के page index करने के hints को चुपचाप control करते हैं।

This tool fetches those response headers for any URL you enter and organizes them into SEO-relevant headers, caching headers, and security headers, flagging which important security headers are present and which are missing. | यह tool आपके द्वारा डाली गई किसी भी URL के response headers fetch करता है और उन्हें SEO-relevant headers, caching headers, और security headers में व्यवस्थित करता है, यह बताते हुए कि कौन से ज़रूरी security headers मौजूद हैं और कौन से missing हैं।

How It Works | यह कैसे काम करता है

Because web browsers block a page from reading another site's response headers directly (a security rule called CORS), this tool routes the request through a public CORS proxy (allorigins.win) so the headers can actually be read and displayed. | क्योंकि web browsers किसी page को किसी दूसरी site के response headers सीधे पढ़ने से रोकते हैं (CORS नाम का एक security rule), यह tool request को एक public CORS proxy (allorigins.win) के ज़रिए भेजता है ताकि headers को असल में पढ़ा और दिखाया जा सके।

If the proxy or the target site itself blocks the request, the tool shows a clear error message and suggests checking the headers manually with your browser's own DevTools (F12 → Network tab) or a dedicated service like securityheaders.com instead. | अगर proxy या target site खुद request को block कर दे, तो tool एक साफ़ error message दिखाता है और इसके बदले अपने browser के DevTools (F12 → Network tab) या securityheaders.com जैसी किसी dedicated service से headers manually check करने का सुझाव देता है।

Q. What are HTTP response headers? | HTTP response headers क्या होते हैं?
They are metadata a web server sends along with every page, controlling things like caching, security policies, and how search engines should treat the content. | ये वह metadata है जो web server हर page के साथ भेजता है, जो caching, security policies, और search engines को content कैसे treat करना चाहिए, यह control करता है।

Q. Why does this tool need a CORS proxy? | इस tool को CORS proxy की ज़रूरत क्यों है?
